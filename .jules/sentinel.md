## 2024-05-18 - High Severity: Insecure curl to shell Execution in Distrobox Helpers
**Vulnerability:** The `db-cuda` and `db-dev` Distrobox helper functions in `modules/programs/shell.nix` downloaded and executed an external installation script (`curl | sh`) to install `uv` inside the containers. This pattern introduces a critical risk of arbitrary code execution if the remote server or DNS is compromised.
**Learning:** The vulnerability existed because the ephemeral nature of standard container images (like `ubuntu:22.04`) encouraged downloading tools ad-hoc during container startup, instead of leveraging the host system's pre-installed tools. In NixOS with Distrobox, the host's `/nix` store is automatically mounted inside the container, making host-installed packages accessible without insecure remote downloads.
**Prevention:** Eliminate all `curl | sh` patterns by ensuring required tools (e.g., `uv`) are installed via Nixpkgs on the host system (`environment.systemPackages`). Distrobox containers can natively access these host binaries via the mounted `/nix` directory, entirely avoiding ephemeral initialization scripts and remote code execution risks.
