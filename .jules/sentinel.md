## 2026-05-24 - Insecure Remote Code Execution (curl | sh) in Distrobox Containers
**Vulnerability:** The `db-cuda` and `db-dev` bash aliases in `modules/programs/shell.nix` previously used `curl -LsSf https://astral.sh/uv/install.sh | sh` to install the `uv` package inside the Distrobox container on startup. This pattern is dangerous as it blindly executes code downloaded over the internet without integrity checks or version pinning, making the environment vulnerable to supply chain attacks or MITM attacks if the domain is compromised.
**Learning:** Distrobox automatically mounts the host's root filesystem (including `/nix/store`) into the container. Because `uv` is already installed on the host via `environment.systemPackages` in `modules/programs/dev.nix`, the container inherently has access to the host's `uv` binary. It is completely unnecessary to redownload and install the binary inside the container.
**Prevention:** Avoid `curl | sh` scripts entirely in declarative NixOS environments. Ensure host tools required in containers are either explicitly managed by the Nix configuration or passed through. Always verify if a tool is already available in the environment before attempting an ephemeral installation.
